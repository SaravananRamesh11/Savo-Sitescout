# M3 tweaks: deviations from the M3 specification

Every item below is something that differs from, or goes beyond, the M3 requirements as written. Nothing here adds a
feature the spec ruled out (no offline support, no catchment-level photos, no extra workflow states, no new tables).

| # | What changed | Why | Where | Required / optional | Impact on M1 / M2 |
|---|---|---|---|---|---|
| 1 | The four "user" columns (`requested_by`, `assigned_to`, `captured_by`, `generated_by`) are **persona-id strings** (e.g. `survey_executive:karthik`), not foreign keys to a User table | This project has **no User/auth table**. M1/M2 identify people with seeded personas carried in the `X-Persona` header. A User table was not created, as instructed | `survey_models.py` (all five tables), `core/personas.py` | Required | None. Same convention as M2's `created_by` / `changed_by` |
| 2 | Tables are created by `Base.metadata.create_all` through `ensure_m3_schema()`, **no Alembic migration** | The repo has no Alembic (M1/M2 use `create_all` plus idempotent DDL). Introducing Alembic would add a second migration system, which was forbidden. All constraints and indexes are declared in the models | `survey_models.py`, `main.py` (startup), `scripts/init_db.py` | Required | None; M1/M2 tables are unchanged |
| 3 | `survey_work_units.workload` (JSON) | Lets the Survey Manager see the workload estimate (lanes, POIs, estimated households, points, basis) before assigning, as required, without adding a table | `survey_models.py`, `catchment_split.py` | Optional but needed for that requirement | None |
| 4 | Property studies use a circle of `CATCHMENT_RADIUS_M` (500 m) around the pin as `study_geometry`; area studies larger than `STUDY_MAX_KM2` (6 km2) are refused | The spec needs a `study_geometry` polygon but not how to derive one. Refusing very large areas keeps one study to a workable amount of ground | `core/survey_constants.py`, `catchment_service.study_geometry` | Required (radius) / optional (size cap) | None |
| 5 | Survey personas activated (`survey_manager:meena`, `survey_executive:karthik`) and a third added, `survey_executive:lakshmi` | Splitting and assigning between people cannot be demonstrated with one executive | `core/personas.py`, frontend fallback list | Required for the demo | None |
| 6 | The M2 transition endpoint, on `CATCHMENT_REQUESTED`, now also **creates the `catchment_studies` row** (and applies reuse). `TransitionIn.force_new` and a checkbox "Run a new survey even if a recent one nearby could be reused" | The request has to create the study record. The override lets the manager survey again instead of reusing | `api/routes/properties.py`, `PropertyReview.tsx` | Required (hook) / optional (`force_new`) | M2 endpoint gained an optional field; behaviour for all other stages is unchanged |
| 7 | **Local conditions** are stored inside `catchment_insights.accessibility_summary["local_conditions"]` | The insights table has no column for them, but they are a required capture category | `catchment_insights.py` | Required by the spec mismatch | None |
| 8 | A reused study is created `COMPLETED` immediately, `reused_from_study_id` always points at the study that actually holds the data (chains collapsed), and its insights are read through that link | Implements "do not duplicate the previous captures" and keeps the previous study and its data | `catchment_service.py` | Required | None |
| 9 | `overall_ground_fit_score` is computed with documented, configurable assumptions (weights in `survey_constants.py`) and only when at least three categories have enough data | The column is in the spec but the formula is not. It is labelled "ground indicator" and **never feeds the M2 score** (confirmed) | `catchment_insights.py` | Optional | None: M2 scoring untouched |
| 10 | Work units are created only when the manager confirms the split **with** assignments; the preview is computed in memory and the OSM payload used is kept in process memory for 15 minutes so the confirmed split equals the preview | A unit has no state without an assignee (states are only ASSIGNED / IN_PROGRESS / COMPLETED), so no half-created units exist | `api/routes/catchments.py`, `catchment_split.py` | Required by the state list | None |
| 11 | The property evaluation created at FINAL_REVIEW carries the survey facts (`metrics.catchment`, a data source line) and the explanation may cite them under the pseudo-factor key `ground_survey`; the property detail `catchment` block is filled (replacing the M2 placeholder `null`) | The final review must show M2 and M3 together. The score, factors and weights are **not** changed | `property_eval.py`, `property_text.py`, `properties.py` | Required | M2 evaluation JSON gains an optional `catchment` entry; scoring unchanged |
| 12 | Extra endpoints: `GET /areas/{id}/catchment`, `GET /catchments/{id}/insights-preview`, `POST /catchments/{id}/insights` (new version), `GET /survey/form-spec` | Needed for the area request card, the review-before-send step, insight versioning and building the phone form from server rules | `catchments.py`, `survey.py` | Required / optional (form-spec) | None |
| 13 | Retired `scripts/advance_property.py` (the M2-time stand-in for the survey stages). `seed_demo.py --reset` now also clears the M3 tables first (foreign keys are RESTRICT) | M3 now drives the stages for real | `scripts/` | Required cleanup | None |
| 14 | Executives can add and **delete** their own observations and photos; an edit API exists but the phone UI has no edit screen | Keeps the phone flow small; `updated_at` and `PATCH` are in place | `SurveyExecutivePages.tsx`, `survey.py` | Optional | None |
| 15 | A capture must fall inside the executive's unit (40 m GPS tolerance) or the server refuses it | Stops observations from being attached to the wrong ground | `survey.py`, `survey_constants.py` | Optional safeguard | None |

Not added: no offline support, no IndexedDB, no service workers, no sync queue, no `client_capture_id`/`sync_status`,
no catchment-level photos, no extra workflow states, no new tables beyond the five, no new dependencies.
